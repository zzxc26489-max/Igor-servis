# The Service and UMC — CRM автосервиса

Внутренняя CRM для автосервиса: запись и подъёмники, заказ-наряды, склад, закупки, услуги, клиенты, сотрудники, финансы, кассовые смены и документы.

## Что уже работает

- заказ-наряды со статусами, работами, запчастями, оплатами и отдельной клиентской печатной версией;
- частичная и смешанная оплата: наличные / терминал / перевод;
- возвраты клиенту и поставщику;
- кассовая смена с начальным остатком, пересчётом и расхождением;
- склад с резервом под заказ, историей движений и закупками;
- дробные складские количества для масел, жидкостей и расходников;
- хранение как по ячейкам, так и без ячейки («быстрый доступ»);
- мини-справочник артикулов: OE-номера, кросс-номера и применяемость;
- внутренние расходники заказа (смазки, очистители, аэрозоли), которые распределяются внутри стоимости работ и не выводятся клиенту отдельной строкой;
- расчёт зарплаты, финансы, отчёты и резервные копии;
- Supabase: авторизация, общая база, роли, синхронизация, офлайн-retry, история и серверные резервные копии;
- сервисная книжка по каждому автомобилю;
- готовые WhatsApp/SMS-сообщения о готовности автомобиля;
- PWA-установка на телефон/ПК и базовый офлайн-кэш интерфейса;
- чек-лист готовности к переходу с демо-данных на реальные.
- два телефона компании и логотип в печатных документах;
- быстрые фильтры прайс-листа по категориям;
- более плотные мобильные списки без лишних вложенных полей;
- роль механика с экраном «Мои работы сегодня» и кнопками Старт / Пауза / Готово;
- роль бухгалтера с доступом только к финансам, отчётам, сотрудникам и документам;
- фото/видео приёмки, диагностики, ремонта и результата в истории заказ-наряда;
- фото перед загрузкой автоматически уменьшаются до 800 px по ширине и сохраняются в WebP quality 0.7 (JPEG fallback), как в MyappforBT;
- сканирование штрихкодов камерой телефона при поиске и приёмке запчастей.

Полное описание требований: [docs/requirements.md](docs/requirements.md).

## Стек

React + Vite + TypeScript + Tailwind CSS v4.

CRM умеет работать:
- локально через `localStorage`, если Supabase не подключён;
- с общей серверной базой Supabase — для нескольких сотрудников и устройств.

Подключение сервера: [docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md).

## Справочник запчастей и VIN

В CRM заложена собственная лёгкая база:
- основной артикул;
- OE-номера;
- кросс-номера / заменённые номера;
- краткая применяемость;
- ссылка на внешний каталог;
- поиск по артикулу, аналогу и автомобилю.

Это не должно заменять профессиональный каталог. Финальная применяемость запчасти всегда проверяется по VIN.

### Куда развивать интеграцию

Наиболее подходящее направление — **TecDoc / TecAlliance**:
- поиск по VIN;
- поиск по OE и артикулу;
- привязки «автомобиль → группа деталей → конкретные артикулы»;
- Web Service API для интеграции прямо в CRM.

Также можно использовать **partslink24** как внешний OEM-каталог: открыть каталог по VIN и перейти к оригинальным схемам/деталям.

Архитектурный план интеграции:
1. В карточке автомобиля кнопка «Подобрать запчасти по VIN».
2. VIN передаётся в внешний каталог/API.
3. Пользователь выбирает узел и деталь.
4. В CRM возвращаются артикул, OE-номер, название, бренд и применяемость.
5. CRM ищет совпадение на своём складе и показывает остаток/ячейку/цену.
6. Если позиции нет — «Добавить в закупки» или «Завести на склад».

Пока API не подключён, вкладка **Склад → Справочник артикулов** работает как собственный мини-каталог.

## Защита данных и одновременная работа

- серверная база имеет ревизии;
- конфликтующие изменения сливаются, а не молча затираются;
- при обрыве сети изменения остаются на устройстве и отправляются повторно;
- чужие изменения подтягиваются автоматически;
- при выдаче CRM повторно проверяет фактический остаток и не даёт списать больше, чем реально есть;
- резерв учитывается по всем открытым заказам;
- резерв запчасти подтверждается атомарно на сервере: два сотрудника не могут одновременно забрать одну и ту же последнюю единицу;
- при конфликте остатка CRM получает свежую серверную базу и показывает актуальное количество;
- при выходе локальная рабочая база очищается с устройства.

## Что ещё осталось перед боевым запуском

Проверьте **Настройки → Готовность к реальной работе**. CRM отдельно подсвечивает:
- телефон сервиса;
- полноту прайс-листа;
- реальные имена механиков;
- замену демонстрационных клиентов/машин/заказов;
- состояние общей базы;
- наличие резервной копии.

Автоматический расчёт сдельной зарплаты уже реализован: начисление идёт по выданным заказам и работам конкретного исполнителя.
