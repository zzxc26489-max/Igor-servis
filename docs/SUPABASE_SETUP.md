# Подключение общей базы Supabase

CRM умеет работать в двух режимах:

- без переменных окружения — старый локальный режим `localStorage`;
- с Supabase — обязательный вход, общая база между устройствами, ревизии, серверные резервные копии и роли.

## 1. Создайте проект

Создайте обычный Supabase project. В SQL Editor выполните файл:

`supabase/001_crm_cloud.sql`

## 2. Создайте пользователей

В Supabase откройте **Authentication → Users** и создайте пользователей Игоря, партнёра, приёмщика и запчастиста.

Затем в SQL Editor:

```sql
insert into public.crm_workshops(name)
values ('Сервис Игоря')
returning id;
```

Скопируйте UUID автосервиса и UUID пользователей из Authentication → Users:

```sql
insert into public.crm_members(workshop_id, user_id, role, display_name) values
('<WORKSHOP_UUID>', '<IGOR_USER_UUID>', 'owner', 'Игорь'),
('<WORKSHOP_UUID>', '<PARTNER_USER_UUID>', 'partner', 'Партнёр'),
('<WORKSHOP_UUID>', '<ADVISOR_USER_UUID>', 'advisor', 'Юра'),
('<WORKSHOP_UUID>', '<PARTS_USER_UUID>', 'parts', 'Запчастист');
```

Роли: `owner`, `partner`, `advisor`, `parts`.

## 3. Добавьте переменные сборки

Project Settings → API:

- Project URL → `VITE_SUPABASE_URL`
- anon / publishable key → `VITE_SUPABASE_ANON_KEY`

Для локального запуска скопируйте `.env.example` в `.env.local`.

Для GitHub Pages добавьте эти две переменные в:
**Repository → Settings → Secrets and variables → Actions → Variables**.

Не используйте service_role key в браузере или GitHub Pages.

## 4. Первый перенос данных

После следующей сборки CRM покажет экран входа.

Войдите владельцем. Если сервер пустой, в **Настройки → Общая база** будет кнопка
**«Перенести текущую базу на сервер»**. Она отправит текущие данные браузера на сервер один раз.

После этого другие устройства после входа загрузят ту же базу автоматически.

## Как работает защита от одновременной работы

У каждой серверной версии есть номер ревизии. CRM сохраняет только поверх той ревизии,
которую пользователь реально загрузил. Если два устройства изменили базу одновременно,
клиент получает свежую версию, переносит свои локальные изменения поверх неё и повторяет
сохранение. Разные сущности (например, разные заказ-наряды) поэтому не затирают друг друга.

## Резервные копии

Перед изменением сервер автоматически сохраняет полную копию базы, если за последние 24 часа
копии ещё не было. Владелец/партнёр также могут сделать ручную копию из настроек.

## Важно про роли

На этом этапе сервер строго изолирует данные одного автосервиса от другого и проверяет членство.
Интерфейс ограничивает разделы по роли. Для абсолютной защиты отдельных финансовых полей от
технически подготовленного сотрудника следующим шагом данные надо разнести из общего JSON-снимка
по отдельным таблицам/операциям с RLS на уровне строк и полей. Не выдавайте доступ к Supabase
Dashboard сотрудникам.
