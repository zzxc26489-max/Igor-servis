# Требования — CRM «The Service and UMC»

## Назначение

Внутренняя CRM автосервиса: запись, подъёмники, заказ-наряды, склад, закупки, сотрудники, финансы, кассовые смены, документы, сервисная история и совместная работа с нескольких устройств.

## Компания

- Название: THE SERVICE AND UMC
- Адрес: ул. Андреевка, вл. 42Г, Зеленоград (гараж №563–564)
- График: ежедневно, 10:00–20:00
- Подъёмники: 5, в перспективе 6
- Телефон: должен быть заполнен перед боевым запуском
- Логотип: `src/assets/logo.jpg`

## Пользователи

Текущие роли сервера:
- owner — владелец;
- partner — партнёр;
- advisor — приёмщик;
- parts — запчастист;
- mechanic — видит только назначенные ему работы без цен, оплат и склада;
- accountant — финансы, сотрудники, отчёты и документы без управления ремонтом и складом.

## Уже реализовано

- заказ-наряды, статусы, работы, запчасти, документы и печать/PDF;
- два контактных телефона сервиса в печатных документах;
- логотип сервиса в заказ-наряде и акте, с возможностью заменить его в Настройках;
- запись по подъёмникам и рабочим часам;
- частичная и смешанная оплата: наличные / терминал / перевод;
- возвраты клиентам и поставщикам;
- кассовые смены и сверка наличных;
- автоматический расчёт сдельной зарплаты по выданным заказам;
- склад: резервы, движения, закупки, возвраты, ячейки и хранение без ячейки;
- дробные единицы склада: литры, миллилитры, кг и т. п.;
- мини-справочник артикулов, OE/кросс-номеров и применяемости;
- внутренние расходники работ;
- клиенты и автомобили;
- сервисная книжка по конкретному автомобилю;
- отчёты по мастерам, услугам, загрузке, времени, расходам и периодам;
- поиск услуг и быстрый фильтр по категориям для редактирования прайс-листа;
- Supabase Auth, общая база, роли, ревизии, merge конфликтов и офлайн-retry;
- серверные резервные копии и восстановление из интерфейса;
- ручной JSON-экспорт/импорт;
- WhatsApp/SMS-шаблон «автомобиль готов»;
- PWA-режим для установки CRM на телефон/ПК и базовый офлайн-кэш интерфейса.

## Данные, которые нужны перед реальным запуском

1. Контактные телефоны сервиса (поддерживается два номера).
2. Полный реальный прайс-лист услуг.
3. Настоящие имена механиков.
4. Реальные клиенты, автомобили и заказ-наряды вместо демонстрационных.
5. Реальные проценты/оклады сотрудников.
6. Проверка реквизитов компании для печатных документов.

В Настройках есть блок «Готовность к реальной работе», который показывает эти пробелы.

## Зарплата

Сдельная часть считается автоматически только по выданным заказам и только по работам, где сотрудник указан исполнителем. Это единое правило для Финансов, Сотрудников и Отчётов.

Окладная часть учитывается при фактической выплате.

## История обслуживания

История строится по `vehicleId`, а не только по клиенту. Для каждой машины показываются:
- все заказ-наряды;
- дата визита;
- выполненные работы;
- использованные запчасти;
- сумма;
- количество завершённых визитов;
- суммарные работы и материалы.

## Уведомления

Сейчас CRM формирует готовый текст и открывает WhatsApp или SMS из карточки готового заказа.

Следующий уровень:
- автоматическая отправка через WhatsApp Business API / SMS-провайдера;
- шаблоны «машина готова», «напоминание о записи», «пора на ТО»;
- лог доставки и статусы сообщений.

## PWA / мобильная работа

CRM адаптирована под телефон и может устанавливаться как PWA.

Текущий PWA:
- standalone-режим;
- manifest;
- service worker;
- кэш интерфейса на случай временного отсутствия сети;
- рабочие данные при потере связи продолжают сохраняться локально и синхронизируются позже.

Для цеха уже реализовано:
- отдельная роль mechanic;
- экран «Мои работы сегодня»;
- статусы каждой работы: не начата / в работе / пауза / выполнена;
- реальные сессии времени по каждой работе.

Следующий этап для цеха:
- камера для фото приёмки;
- сканирование штрихкодов камерой;
- фото/видео к внутренней истории заказа.

## Склад и конкурентная работа

Сейчас:
- резерв учитывается по всем открытым заказам;
- перед выдачей повторно проверяется фактический остаток;
- конфликтующие версии общей базы сливаются.

Для последней единицы товара следующий уровень — отдельные атомарные RPC/таблицы Supabase:
`reserve_stock(item_id, qty, revision)` и `release_stock(...)`.
Так сервер сможет гарантировать, что два пользователя одновременно не зарезервируют одну и ту же последнюю единицу.

## Интеграция каталогов запчастей

Текущий мини-справочник поддерживает:
- основной артикул;
- OE-номера;
- кросс-номера;
- применяемость;
- ссылку на источник;
- поиск по автомобилю/номеру.

План: интеграция TecDoc/TecAlliance или внешнего OEM-каталога по VIN, с возвратом выбранной детали обратно в заказ/закупку/склад.

## Техническая база

Frontend: React + Vite + TypeScript + Tailwind CSS v4.

Серверный режим: Supabase.

SQL-миграции выполняются по порядку:
1. `supabase/001_crm_cloud.sql`
2. `supabase/002_role_security_admin_tools.sql`
3. `supabase/003_cash_shifts.sql`
4. `supabase/004_mechanic_accountant_roles.sql`
